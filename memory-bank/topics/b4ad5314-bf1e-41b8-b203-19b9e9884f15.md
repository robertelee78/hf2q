# Gate campaigns: any candidate failure fails the gate; a failed comparison-arm run is rerun

Operator decision of 2026-11-12 for Q4 release-gate campaigns ("strict on us, fair on them"), recorded in ADR-063 (Q4 acceptance, "Comparison-arm failure amendment") and implemented in PR #837 (merge 5f9682ee):

- Candidate (the experiment arm): any failed run, warmups included, makes the family verdict `Failed` at once. The candidate is never rerun.
- Comparison arms (stock v0.1.29, the peer, Splash): a run that fails its own task is kept, counted, reported and rerun at once in the same block position, at most 2 reruns per position. Speed is paired on passing runs only. A passing run is never rerun.
- Three failures in one position make that arm `Unavailable` for the family (not `Failed`, never a `Win`).
- Only outcome `Fail` of kind `task` is rerun. Out-of-memory stops, a server exit, an invalid run and a run that did not start keep their earlier handling.
- No threshold, margin or block count changed. The rerun count is frozen in the campaign plan; a campaign planned before the change can only be resumed from the harness commit that started it.

Evidence supplied with the decision (a measurement, not the rule): over the `campaign.json` records of the five Qwen3.6 gate campaigns of November 2026 (M5 Max 128 GB), task failures were stock 4 of 24 runs, the peer 1 of 22, Splash 1 of 20, and the experiment arm of that time 1 of 23.

Two consequences ADR-063 states, to plan for:

1. Establish the candidate's pass rate on the campaign's exact case before launching a gate campaign. The second combined candidate (ADR-067, campaign `qwen36-w2-all-d5-v1`, binary `ff578ce3`, mlx-native 0.21.9) emitted the same 5,322 completion tokens in all ten Qwen3.6 runs and passed 10 of 10. A candidate that repeats its output passes a given case every time or fails it every time, and one candidate failure ends the campaign as `Failed`.
2. The stock arm's failures look repeatable on some cases (two back-to-back failures with identical token totals in `q4-qwen36-closing-84b54098-v2`), so an exhausted position and an `Unavailable` campaign have to be budgeted for on Qwen3.6.

No real-model campaign had run under the new rule when PR #837 merged. ADR-063 on main is the authority for the exact rule; read it before planning a campaign.
