# Never export MLX_PROFILE_CB in a timing run

Do not export `MLX_PROFILE_CB` to a process whose time is being measured, not even as an empty string. mlx-native up to 0.21.6 turns per-command-buffer profiling on for any present value, and that makes every labeled commit synchronous.

Set it only for a diagnostic category profile, together with the explicit stage profile (`HF2Q_ADR065_STAGE_PROFILE=1` requires `MLX_PROFILE_CB=1`), and do not compare those times with unprofiled ones. A valid timing run prints no `[CB_PROFILE ...]` dump.

What happened: the Q5 Qwen3.8, Gemma 4 and DeepSeek-V4 cases exported `MLX_PROFILE_CB=""`. Every Qwen3.8 run launched from them from 2026-11-09 until the supervisor fix ran with synchronous labeled commits (188 retained runs). Same binary, identical output: 72.072 and 69.694 s with the empty variable, 61.145, 60.267 and 60.089 s without. Absolute times from that period are inflated, and accept/reject decisions measured under it have to be re-measured before they are relied on; ADR-067 names which were redone. Gemma 4 and DeepSeek-V4 production paths issue no labeled commits, so their runs were not affected (source reading, not re-measured).

The fix: the Q5 supervisor no longer exports a case control left at its empty default.
