# A kernel written over the Metal tensor API needs an availability check with two cases

A kernel whose shader uses the Metal tensor API cannot run on every host hf2q supports. Two different hosts lack it, and they fail differently:

1. The runtime Metal compiler has no `<metal_tensor>` header (macOS before 26). The shader does not compile.
2. The GPU is outside the Metal 4 GPU family under macOS 26 (a virtual machine; GitHub's hosted macOS runner reports "Apple Paravirtual device"). The header exists and the shader compiles, then pipeline creation fails (`unsupported deferred-static-alloca-size function body in ...cooperative_tensor...`).

A check that only looks for the missing header misses case 2. mlx-native 0.21.9 did exactly that in its dense matmul route: it fell back to the simdgroup kernels in case 1 and returned an error in case 2, so no dense quantized matmul of more than eight rows ran on the hosted runner (found on PR #835's hosted `tests` job; hf2q carries a recorded test skip for it, PR #836, to be removed with the pin that carries the fix).

What to do:

- Any route that selects a tensor-only kernel (the prepared GGUF matmul and the other DFlash2 route-profile kernels have no portable twin) must ask whether the kernel family is available on this host before it is selected, and decline to the stock route when it is not. A failed build on a Metal 4 device is a defect and must stay an error, not a fallback.
- This has to be in place before such a route becomes a default.
- Hosted CI is a case-2 device, and its `tests` job runs only a whitelist of test filters (for example `qwen38`). A tensor kernel reaches that device only if a test under one of those filters dispatches it; real-Metal suites outside the whitelist never run there. A green hosted job is not evidence that a new tensor kernel is safe on such hosts; a case-1 host is not covered by the hosted job at all.

State when recorded (2026-11-12, origin/main 5f9682ee, mlx-native pin 0.21.9): mlx-native #154 (tensor probes treat both cases as unavailable) merged at 7784d783, unreleased; mlx-native #157 (availability query for tensor-only kernel families, typed `Unavailable` error) and hf2q #839 (`inference::route_host` declines tensor-only fast routes) open, in review. Check the pin and main before relying on any of them.
