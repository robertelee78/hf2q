# Compare with Splash at equal GPU clock

Rule: before comparing an hf2q stage or cycle time with a Splash figure, or two hf2q runs taken at different times, put the GPU performance state beside both numbers. A Splash `decode-profile` number and an hf2q served (in-situ) number are not at the same clock.

On main (ADR-067, "Second combined candidate and the end-to-end comparison with Splash", origin/main 5f9682ee):

- A run's GPU speed follows the GPU clock. Over eleven Qwen3.8 runs with a 100 ms performance-state sampler beside them, the 16 layer commands of a cycle took 50.3-53.2 ms at 1,470-1,506 MHz and 60.9-63.1 ms at 1,133-1,189 MHz (r = 0.97 across run means). Builds and other work on the host lower the clock.
- A stage gain under about 5% needs the behaviour alternated inside one process, or the sampler beside every run. Campaign arms run back to back on an otherwise idle host.
- Splash's own served cycles are slower than its synthetic profile (Qwen3.6, four lanes: about 28 ms served, 20.8 ms in the profile).

Measured 2026-11-12, one ticket, sampler beside each program (Qwen3.8, M5 Max 128 GB; pair `splash-clk1` / `q38-base-clk1`, hf2q binary `ff578ce3`, Splash commit 031a25a6; written in PR #838's ADR-067 text, not on main when recorded):

- Splash's `decode-profile` tool held the GPU at its top state: mean 1617 MHz in its fused four-lane cycles (51.59 ms), 1620 MHz in its attributed cycles.
- The hf2q server, minutes later, ran its four-lane cycles at a mean of 1394 MHz (59.66 ms period, 16 layer commands 46.79 ms).
- Within the hf2q run the layer commands fit 10.3 + 51,088 / MHz ms (r = 0.96). Fitted to 1620 MHz they take 41.85 ms against Splash's 42.72 ms for the same stages. The earlier "4.6 ms in the layers" was the clock; at equal clock the remaining distance (about 2 ms) was the cycle's tail.

Inference, not measurement: the 1620 MHz hf2q figures extrapolate a within-run fit over 1280-1547 MHz. hf2q was never observed at 1620 MHz in a served run.

Not established: what holds the served GPU below the top state, and whether a served Splash holds it (no valid served Splash run on Qwen3.8; its Qwen3.6 served-to-profile ratio suggests it does not).

So every earlier Splash tool number is a top-state number and every hf2q in-situ number a lower-state number. Do not open stage work on a gap between the two before it is restated at equal clock.
