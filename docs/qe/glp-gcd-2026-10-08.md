`hf2q chat`, the OpenAI-compatible API, and OpenCode, on Qwen3.8 and

## Findings

1. **`hf2q chat --model X --glp V` served the model unsteered (fixed, #271).**
   - Symptom: the chat-started server's command line carried `--glp`, yet
     `/hf2q/v1/runtime` reported `glp_active: false`. Its answers matched the
     unsteered baseline word for word. `hf2q chat X --glp V`, with a
     positional model, worked.
   - Cause: serve resolved `--glp` only inside its startup `--model` branch,
     and every later load used a template with `glp_path: None`. Chat starts
     serve without a model and activates it afterwards.
   - Fix: GLP is now server-wide policy, resolved on every load path, failing
     closed with a typed diagnostic. ADR-053 records the root cause.
   - Severity: high. Users believed steering was on.
2. **Stock OpenCode failed against DeepSeek-V4 (fixed, #270, issue #269).**
   OpenCode's `bash` and `read` tools declare ±2^53 integer bounds. hf2q's
   integer-range grammar doubled per digit, so two such tools exceeded the
   4 MiB grammar limit. 0.1.22 returned a 400. 0.1.21 crashed the server.
   Severity: high.
3. **`--gcd` breaks tool calling under `tool_choice: "auto"` (#255, open).**
   Seen on Qwen3.8 and DeepSeek-V4, over the API and through OpenCode,
   including a fabricated file read.
4. **`--gcd-schema` at a too-small token limit returns HTTP 500 (#256,
   open).**
5. **The QE playbook's J7 command could never succeed (fixed, #267).** The
   GLP-49 repository holds two vectors, and `HOME=$QE_HOME` hides a normal
   `hf auth login` token. J7 now names one file by URL and passes `HF_TOKEN`.
6. **DeepSeek-V4 printed a `[GLP-DEBUG]` line on every serve (fixed, #268).**

## Impressions

- Qwen's engine logs nothing at default verbosity when it binds a GLP vector,
  while DeepSeek-V4 prints a "[GLP] vector bound" line. Chat's `/status`
  shows neither GCD nor GLP. The runtime endpoint is the only way to confirm
  steering is on.
- Without `hf2q setup`, a fresh home serves Qwen with `fifo-serial`, which
  refuses prompts over 2,048 tokens with a clear `--scheduler
  inflight-batched` hint. OpenCode's system prompt alone is 2,174 tokens.
  Setup records inflight-batched and the installer tells users to run it, so
  this is documented. OpenCode then retried the rejected request thousands of
  times.
- After a successful convert, two empty `*.conversion-operation.pair.lock`
  files remain beside the output, one for an mmproj that a text-only model
  does not have.
- The Qwen GLP-49 L10-58 vector made Qwen add authorization caveats and
  reason roughly twice as long before answering the port-scanner request.
  Whether that is the vector's intent is for its author to judge.
