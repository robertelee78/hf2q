## 3. Cache compatibility decision (§5, blocking condition)

**Decision: the bounded family identity epoch. No proof of prior overlay
non-admission exists, so the fallback policy applies.**

Current-main verification: no kv_persist fingerprint, block-store identity,
or LCP registry key includes overlay state (a source sweep of
`src/serve/kv_persist/*.rs` and `src/serve/api/state.rs` for
overlay/affine terms in identity/hash/fingerprint contexts returns
nothing). Therefore pre-retirement caches created under an active overlay
cannot be distinguished from plain caches by the post-retirement binary,
and R2 must introduce a one-time identity epoch for the affected families.

**Composition with the graft-era identity machinery (new since the plan was
written):** main now carries `steering_and_graft_params_hash`
(`src/serve/api/engine_qwen35.rs:1777`, with the gemma4 twin noted at
:1742) binding GLP + graft state into cache identity. The epoch is to be
folded into these same hash functions at R2 (a retirement-version
component), not bolted on as a separate global format change. Effect: all
pre-retirement caches for the affected families miss exactly once; files are
preserved on disk; fresh cache reuse after restart is verified in R2's
admission tests. No cache leak is claimed — this is the recorded
operational cost, per §5.
