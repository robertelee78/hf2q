# ADR-040 §0.19 — Decode non-determinism: root localized + scope pivot (2026-06-27)

## TL;DR

- **The single-process N=8 continuous-batching product is COHERENT.** Single-process (no
  GPU contention) N=8, MAXTOK=32, REPEATS=6 = **0/40 every run, 0/120 across 3 runs**.
  Greedy (temp=0) is bit-reproducible run-to-run. The primary goal — "N=8 continuous
  batching as coherent as llama.cpp" — is met for the actual product (one process, 8
  KV-slots, one GPU context).
- **§0.19 is a cross-process (multi-tenant) phenomenon only.** It manifests when **two
  separate server processes** share one GPU. Root: hf2q's 4-bit TQ-HB-V quant amplifies
  cross-process GPU-occupancy jitter into token flips; llama.cpp (F16/Q8 V, no amplifier)
  stays byte-identical.
- **Prefill §0.19 is closed** (shipped 609dfdc6): MAXTOK=1 under 2× contention ≈ 1/288
  (deterministic).

## The reliable repro (the prerequisite that blocked prior sessions)

Two ingredients, both required:
1. **NSEQ=8** (default), not NSEQ=1. NSEQ=1 isolates single-stream decode and bypasses the
   batched same-bucket flash path — it reads ~0 always. Prior decode diagnosis used NSEQ=1
   and was therefore on a weak repro.
2. **Two contending processes** (each loads the gguf; ~40 GB total — 4× exhausts memory).

With both: flakes **every round** (~31% per-(repeat,slot)). Single-tenant is deterministic.
Drivers: `scratchpad/calib_*.sh` (ABAB-interleaved baseline-vs-intervention).

## Root localization

`HF2Q_FULL_F16_KV=1` (store V as F16, no FWHT/4-bit quant) = **0/24 every round, 10/10
clean** under 2× contention while baseline flakes every round (ABAB-interleaved). So
§0.19-decode **requires the TQ-HB-V quant path** — the exact hf2q-specific kernel family
llama.cpp lacks (explains llama's immunity).

Localized to **decode step ≥2**: MAXTOK=1 ≈ deterministic (1/288); the flake accumulates
over autoregressive steps (the unique step-≥2 differential is the KV cache now containing
decode-written positions). Consistency signature: **run 0 ≠ runs 1..N, but runs 1..N agree**
— run 0 = peak simultaneous contention, runs 1..N de-sync to lower contention. Not random
whole-buffer corruption (that would scatter per-run).

Mechanism (leading): 4-bit Lloyd-Max boundaries are coarse (~0.1–0.25 steps); a ~F16-ULP
upstream V jitter (only at peak contention; harmless and averaged in smooth F16 attention)
is discretized by the quant into a full codebook-step (~0.25) output error — a ~500×
amplification → one V element flips → one token flips → greedy cascade. F16 storage doesn't
amplify (jitter stays ~0.0005) → clean.

## Hypotheses validly refuted under the reliable repro

(All prior refutations were suspect — done single-tenant / NSEQ=1 before the repro existed.)

- **Intra-process concurrent-dispatch race** — `HF2Q_FORCE_SERIAL_DISPATCH=1`
  (MTLDispatchType::Serial, zero intra-encoder concurrency) still flakes 5–9/24.
- **Residency sets** — `HF2Q_NO_RESIDENCY=1` still flakes.
- **Split-K reduce** — `HF2Q_HYBRID_NWG=1` (no tmp+reduce) still flakes.
- **Batched-vs-per-slot flash kernel** — `HF2Q_BATCHED_FLASH=0` still flakes. (The prior
  memory claim "BATCHED_FLASH=0 → mostly clean" was a variance artifact.)
- **OOB / foreign-buffer aliasing** — `MTL_SHADER_VALIDATION` + `GLOBAL_MEMORY` (headless)
  fires nothing; encoder binding-watch shows only `hidden`'s own range bound at its address.
  Validation's GPU-serialization SUPPRESSES the flake (→ occupancy-sensitive, not a stomp).

This supersedes the prior session's "elusive whole-buffer corruption / frame-capture-only"
framing — §0.19-decode is the TQ-V path, not generic memory corruption.

## Multi-tenant mitigation + open decision

Proven mitigation for full 2-process-contention coherence: `HF2Q_FULL_F16_KV=1` (V cache
F16), at ~2× total KV-cache memory (V 0.5→2 B/elem; K already F16). The exact corrupting op
within the TQ-V path is un-pinned because every TQ-V kernel is structurally deterministic
(single-simdgroup, register + simd_shuffle_xor, zero threadgroup memory, no atomics) and the
per-layer-finish checksum instrument suppresses the flake (heavy serialization reduces
cross-process co-scheduling overlap). A non-suppressing probe (Metal frame capture, or an
end-of-decode persistent-KV-cache K(F16-control)-vs-V(4-bit) checksum) is the next tool if a
TQ-V-preserving fix is pursued.
