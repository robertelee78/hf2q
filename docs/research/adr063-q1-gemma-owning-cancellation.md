# Q1 Gemma T6 owning cancellation (prospective source)

This test-only extension uses the actual owning-worker transaction and reply,
not a fabricated forward failure, direct restore or another family's cache.
No real-model T6 result or new numerical policy is claimed.

For each of four distinct logical agents/physical slot IDs, the adapter creates
the real Gemma4PrefillState with the frozen128 prompt and stable_boundary64,
real scheduler admission/SlotHandle, unary oneshot sender and live receiver,
production Gemma4KvGuard, retained-token/anchor ledgers and supervisor. The
first actual advance64 must install Pending, carry the actual stable64 anchor,
leave the receiver open and validate every real scaffold's cursor64. Full
active64 capture follows that successful checked return.

One cfg(test) hook sits after real state.advance returns and before its actual
Pending/Ready installer. It closes the actual receiver only on success with
the exact slot/generation and checked cursor128. It never fires on Err; wrong
owner/cursor fails. The second real suffix64 advance returns Ready and enters
the existing client_closed branch. Existing recovery selects the returned
stable anchor, restores Hybrid ring bytes and cursor64, restores retained
prefix tokens, releases the real reservation, and completes the cancelled
reply without seed publication. The adapter requires empty owned work, exact
retained prefix64 and anchor64, healthy supervisor and zero in-flight slots.
Invalidation to0 or unrelated failure cannot satisfy it.

A same-thread RAII capture lease pauses only this unpublished cancelled tail.
It does not alter native execution or add waits. Canonical capture is restored
before replay64..127 and the16 actual scalar inputs128..143. An incomplete
previous canonical call cannot be paused; new capture installation while paused
is refused. The full144 canonical endpoint/caches remain mandatory. This is
not T2 physicalB4, and T5 still lacks a real Gemma proposal adapter.

Both active64 captures are saved in the ordinary config-derived manifest,
with restored roles disambiguated by segment+1000. After the full trace is
written, require_restore64_exact checks every paired coordinate, scalar,
shape, byte count and full-content hash. A differing or missing pair is a
failure, and the execution report is retained before returning that failure.
Float continuation remains Unspecified/Inconclusive; exact packed U8 restore
is encoded KV identity, not an expert-ID invariant. Independent artifact and
source/build/model/workload joins remain required before qualification.

## Finite ordinary adapter correction found during this authoring

The reviewed first ordinary source called the slot-aware weight primitive
then checked persistent scaffold cursor, but the primitive deliberately leaves
host publication to its owning engine. No actual ordinary model run had been
performed. The adapter would fail closed at its first cache capture. This
extension calls a narrow cfg(test) wrapper around the SAME production
commit_gemma4_slot_cursor after each successful ordinary prefill/scalar return,
with the real expected-before/end. It validates the cursor rather than setting
it by hand. T2 already used those production publication helpers. T1 Hybrid
restore64 keeps the idle owner/HB64 consistent. No production math, serving
policy, cursor validation or historical evidence is relaxed or rescored.

The selected source anchor requests158,105,600 bytes, live one serial logical
lane at a time. T6 additionally processes one unpublished64 suffix per lane;
that work is charged, not counted as canonical144 outputs. The full canonical
logit/cache plus before/restored64 payload is precomputed before load, as for
T1, within the explicit host payload limit. Root's model/cache/driver/metadata
operating packet is still separate and mandatory.

Hosted controls exercise the actual one-shot guard (Err, stale owner/cursor,
exactly once, nested/disarmed), the real capture pause boundary and actual
exact64 hash gate. None fabricates a Metal/model transaction. Root must compile
and run those controls, review a frozen packet, and obtain independently
reviewed actual Gemma captures before any runtime acceptance.
