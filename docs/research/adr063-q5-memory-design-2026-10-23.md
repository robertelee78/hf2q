# ADR-063 Q5 memory qualification proposal

Status: proposed design, not reviewed or approved. Author: q5-design-agent. No builds, model loads, source changes, or execution qualification were performed. Source inspected: hf2q 5b385d4ff580cc2c9cc70cdb425809b0c64dff63 and mlx-native f92eb020c4d3f821700e648fbce15d6cf75c2cc6 (0.15.1). F1 remains an execution predecessor; this proposal does not authorize Q5 full-model runs.

## Observable contract

Before loading, and before every allocation transition that can raise the peak, require a checked, conservative projection of all simultaneously owned memory. For physical RAM P, reserve R >= 12 GiB, optional additional whole-process family ceiling F, and observed competing nonreclaimable use C, require both projected process ownership B <= F (when F applies) and B+C+R <= P. The candidate cap is min(F, P-R-C), or P-R-C when a complete ceiling inventory establishes no additional family ceiling. C is external competition in bytes and reduces the host bound, not the independent process ceiling. All arithmetic must be checked and a missing required allocation term must reject qualification. Distinguish an unknown ceiling inventory from a verified absence of an additional family ceiling; the latter does not block use of the unconditional host bound. On a 128 GiB host, 116 GiB is only the zero-competition upper bound. If the existing family ceiling is lower, it wins. Do not substitute an allocator or KV limit for F.

The accounting contract for C needs review before implementation: sum distinct competing processes using physical footprint where available, with a documented conservative fallback, and explicitly identify OS/kernel use covered by the reserve. Do not subtract the same memory through both an available-memory value and competitor totals. Fail if trustworthy observations cannot be obtained. Existing DeepSeek launcher guards remain additional constraints: its largest-process test is not an aggregate-competition measurement.

A rejected frozen workload is reported as unadmittable. Do not quietly reduce context, result bounds, slot count, KV budget, anchor coverage, or drafter participation to produce a pass. A pressure stop is a failed qualification, not a successful bounded run.

## Disjoint ownership ledger

Maintain an allocation identity and its backing identity internally, without writing pointers to public receipts. Attribute each physical allocation once; owner references and residency membership are not allocations. Represent host bytes separately from shared Metal-backed bytes. Report four distinct quantities rather than summing them: logical workload budget, unique owned allocation/capacity bound, process physical footprint, and Metal resource/residency diagnostics.

1. Weights: mapped backing pages including alignment/gaps, plus independently allocated expanded/dequantized tensors and host load staging. Native GgufFile::mapped_tensor_storage_plan supplies metadata-only page-rounded mapped segments (mlx-native/src/gguf/mod.rs:1710). GgufMappedTensorSet::physical_byte_len is the allocated mapping measure. Tensor views are references into those segments. Deepseek4Weights::resident_bytes is explicitly logical tensor storage (hf2q/src/inference/models/deepseek4/residency.rs:203), not a complete physical measure. Expanded elementwise tensors coexist with mapped originals where the mapping includes them.
2. Four-slot live state: attention KV parents, quantized KV legs/norms, recurrent and convolution double buffers, indexer/compressor states, MTP state, and capacity reserved for the declared context. Deduplicate slot views and parent views. DeepSeek window_kv and compressed_kv alias attention_kv (deepseek4/cache.rs:408-437); count the parent once, not all three. Distinguish lazy overwrite capacity from currently committed pages; low current RSS does not prove eventual capacity fits.
3. Recovery state: all four slots' committed and pending anchors, including host Vec capacities and associated metadata/token storage. DeepSeek capture_turn_anchor preserves committed while allocating pending (engine_deepseek4.rs:1261 onward). Qwen HybridKvSlotAnchor and GemmaHybridSlotAnchor store host copies (qwen35/kv_cache.rs:1011, gemma4/kv_cache.rs:1607); these are additional physical memory, not Metal views. Include full snapshots when the exact path uses them. Avoid adding an anchor twice when consuming an estimate already inclusive of an anchor.
4. Drafter/speculation: separate draft model weights, draft caches/recurrent state, verifier state, hidden-state ownership, and speculative request buffers. A small hidden view can pin a much larger parent: MlxBuffer::byte_len is root resource size while data_byte_len is logical view size (native/src/buffer.rs:328-337). Count the parent once across all owners.
5. Scratch: free retained pool buckets, active allocations, persistent matrix/cohort buffers, CPU-written submission input buffers, recorded dispatch references, and resources retained by queued command buffers until completion. Bucket capacity can approach twice requested bytes (native/src/buffer_pool.rs:34). Pool reset transfers in-use to free; it does not free memory. Residency registration of external buffers must not count them again. DeepSeek's current scratch statistics expose only free bytes (forward_support.rs:28,120-157), so they cannot establish the peak.
6. Host/service and transition overhead: tokenizer/model metadata, request and output buffers, logits/token vectors, disk anchor serialization/hydration images, and the bounded host runtime baseline. Cache growth must include old plus new caches until migration completes (engine_deepseek4.rs:1066-1079). Capture, restore, cancellation, and failed requests must each have a peak/lifetime description. Include load-time and unload-time overlap, not only steady state.

Do not add process footprint or Metal currentAllocatedSize to the ownership ledger: both overlap allocations already counted. Use them to falsify incomplete accounting and report unexplained positive gaps. Residency set removal is not proof of deallocation; native MlxBuffer storage is Arc-owned, recorded bindings clone buffer references, and command buffers retain resources (native/src/buffer.rs:54, encoder.rs:954,1220).

Resolved conservative mapping choice from independent review: use the native checked, page-rounded resource-span sum for preload accounting, and charge Metal device setup separately. Native plans sum page-rounded segment lengths. Independently split segments can cover a shared file boundary page (native/src/gguf/mod.rs:2036-2082). Exact physical union would need backing-file intervals, not a sum of resource references; that precision work is optional, not a safety prerequisite. Conservatively retaining the sum is safe but must be labeled an allocation bound rather than exact unique resident pages; do not subtract overlap without proof.

## Existing limits and immediate falsifiers

ADR-042 defines the DeepSeek artifact ceiling at 108 GB decimal and peak process footprint at 116 GiB, with critical pressure or material steady swap growth as falsifiers. ADR-049 repeats the 116 GiB peak condition and preserves a 2048-row cooperative prefill bound; do not raise it. The 100,000,000,000-byte branch in verifier_forward.rs is a scheduling threshold, not admission authority. Existing Qwen/Gemma KV budgets and scheduler admission are KV scoped, not whole-process ceilings. The applicable stricter family ceilings must be inventoried and explicitly recorded before implementing F; none should be fabricated from the artifact sizes.

Verified artifact byte sizes supplied for this design: Qwen3.8 16,810,714,976; Qwen3.6 21,712,410,208; Gemma4 16,796,018,144; DeepSeek4 107,431,343,264. These are identity/size inputs, not complete physical admission estimates. The supplied DeepSeek model+four-slot KV estimate of 106.96 GiB at context 262144 and 8 GiB KV budget omits enough categories that it cannot authorize loading. In particular load_info.rs:590-605 includes live fixed state plus one recovery image, while committed-plus-pending replacement and old-plus-new growth can add further overlap. No positive safety claim follows from the apparent 9.04 GiB difference to 116 GiB.

## Smallest implementation boundary

First implement a pure hf2q ledger and checked peak projection driven by explicit allocation/lifetime events, with serialized receipts and fail-closed missing categories. Keep workload/family policy, competing-use observations, reserve, and admission decisions in hf2q. Reuse the existing native metadata-only mapping plan rather than allocating a model to estimate it. Preserve scheduler transient versus impossible request errors; whole-process qualification needs its own explicit reason.

The smallest sufficient native addition is ownership-aware resource identity and lifetime accounting spanning direct allocations, pools, residency-retained roots, recorded graphs, and in-flight command buffers. Pool-only counters or a registry ending when MlxBufferStorage drops are insufficient because Metal handle clones outlive that wrapper. Charge queued retention sets until completion and persistent captures until destruction; deduplicate all retention references against their root. Expose opaque monotonic IDs and state labels, not raw addresses. Required pool/resource statistics include: unique retained bucket bytes in free and in-use sets, external-registration bytes reported separately, and high-water/command-completion lifetime accounting. Current free-only statistics are insufficient. Whether to implement a single allocation registry or narrowly expose pool statistics plus dispatch lifetime counters needs review against actual ownership coverage. A resource ID must remain stable across views and references; do not expose raw addresses. Include tests in native and publish native before hf2q pins it if native APIs change. No kernels need to move into hf2q for this work.

Use one hf2q admission authority to serialize atomic reserve/commit/release across all four slots and transitions. Reserve the entire overlapping transition before beginning allocation; a check followed by independent allocations races. Failed allocation preserves prior valid state and releases only proven-unused reservation. Reserve projected transition memory before dispatch/allocation; periodic OS samples alone cannot prevent a between-sample overshoot. Sample physical footprint, VM pressure, wired/compressor pages, pageins/pageouts, swapins/swapouts, compressions/decompressions, and competitor footprint with timestamp and maximum sample gap. Existing Darwin VM test helpers provide most counters (deepseek4/real_artifact_decode_cohort_tests.rs:239-270); physical footprint must be added or separately collected. Missing/stale samples stop qualification. External competition can grow asynchronously, so promise a measured bounded detection/stop latency, not instantaneous prevention. On pressure failure stop new dispatch, drain bounded outstanding work, then release resources. Choose and measure sampling cadence before timing evidence; receipts must declare it. Metal allocation/residency counters are cross-checks and device limits can impose an additional independent bound.

## Negative controls before real weights

- Checked arithmetic overflow, negative headroom, unknown family ceiling, omitted required category, and stale/missing host sample reject without allocating.
- Four tiny views of one large root count once at root size; a tiny retained hidden view keeps the root charged. Separately allocated copies count separately.
- Mapped tensors sharing pages count once within a mapping; segmented alignment is conservative until unique backing-page behavior is proved.
- DeepSeek parent/window/compressed views count the parent once, but four independent slot parents count four times.
- Growth charges old+new until migration and completed command buffers release old ownership; anchor replacement charges committed+pending, including failed/cancelled publication.
- Free pool buckets still count, bucket rounding counts, reset does not reduce total ownership, clear only releases truly unreferenced/completed resources, and external residency registration cannot duplicate the allocation total.
- Several competitors individually below the launcher threshold but collectively above remaining headroom reject. Competition appearing after load causes a bounded stop before the next projected allocation.
- Load staging, host anchor image export/hydration, draft weights and scratch cannot be removed from the ledger by changing view labels or phase names.
- A frozen four-slot workload that fails admission remains failed; tests assert it cannot pass by reducing context/result bounds or silently disabling speculation.

Use small synthetic allocations or pure event fixtures. Do not emulate pressure by deliberately exhausting this host. A recovery test must demonstrate GPU completion plus ownership release before asserting cleanup, and demonstrate that a failed restore never publishes a partially restored anchor.

## Bounded real-model qualification sequence

Only after F1 and independent design review, run pure controls and metadata preflight for all four exact artifacts. Freeze commits, artifact hashes, four-slot context/result limits, prompts, sampling, cache and drafter configuration, scenario order, and reference settings. Reject an unbounded scratch path before a full-model load.

Prove instrumentation and cleanup first on a model with demonstrably admitted headroom. Run one engine/model process at a time, including stock, candidate, and peer. Verify listeners/processes and memory recovery before loading the next engine; never co-reside DeepSeek engines. Existing model files should be reused and hashed, not downloaded unnecessarily.

For each admitted family, exercise four actual occupied slots with the largest declared context/result workload; include staggered prefill, mixed decode/prefill, cache growth, anchor replacement, divergence/rewind, tool-result continuation, cancellation, and configured drafter/verifier paths. Use deterministic bounded tool rounds and explicit output caps, with matched stock/candidate/peer workload. Record per-phase projected peaks, observed footprint peak, logical cache usage, pool active/free and in-flight bounds, pressure and swap/compression deltas, cache reuse, TTFT/prefill/decode and semantic/tool correctness. Sampling and profiling overhead must be held constant or separately qualified.

DeepSeek is last and only proceeds if the complete conservative pre-load/transition projection fits the stricter cap. The static 106.96 GiB figure does not meet this prerequisite. No full-context attempt should be used to discover an unknown allocation bound. Stop before the next allocation when projected headroom is breached or telemetry is unavailable, and immediately on critical pressure or prohibited growth. Unload, wait for completion, and record bounded recovery relative to the pre-load baseline. Define allowed residual mapped/file cache versus actual process/resource leaks explicitly.

Q5 memory acceptance requires an independent reviewer to reconcile projected versus observed peaks and unexplained deltas, validate the admission/lifetime proof and matched measurement envelope, and preserve all existing quality/serving gates. Q5 accounting need not itself create a speed win. Repeatable speed wins for all four remain the separate overall ADR-063/Q3/Q4 duty, with Qwen3.8 and DeepSeek4 first priority. This design proves neither memory qualification nor speed outcomes, and grants no runtime approval.

## Questions requiring decisions/evidence

The [family ceiling inventory](adr063-q5-family-ceilings-2026-10-23.md) resolves the initial ceiling search: no additional whole-process ceiling was found for the Qwen/Gemma families; DeepSeek retains 116 GiB. The implementation must distinguish this explicit absence from an unknown or uninspected contract. Remaining questions below are evidence requirements, not permission to invent missing numbers.

1. What are the existing whole-process ceilings for each Qwen/Gemma family and each frozen workload? Are any stricter than physical-minus-reserve-and-competition? Complete a repository-wide inventory and record source, units, scope, and an explicit optional ceiling; verified absence is distinct from an unknown inventory. The Qwen/Gemma 48 GiB shared KV budget is not a process ceiling.
2. What exact reserve/competition definition avoids counting OS memory twice, and what privileges/tools provide dependable per-process nonreclaimable measurements on this host? How should shared memory across competing processes be conservatively bounded?
3. Resolved for the initial design: use the conservative native resource-span sum, including duplicated boundary-page coverage, plus device setup. Backing-page union is optional later precision work; conservative rejection remains a rejection.
4. Which minimal native counters cover all active/free/persistent/queued scratch ownership without instrumenting only one pool and missing another? What bounds exist for every supported cohort/prefill row shape?
5. What exact four-slot contexts, result bounds, drafter artifacts, and anchor persistence modes are the frozen qualification matrix? They cannot be selected after observing memory failure.
6. What threshold constitutes material swap/compression growth, what sample freshness/cadence is acceptable, and what residual cleanup bound/time window is required? Existing launcher startup ceilings do not answer run-delta acceptance.
7. Can the peer provide equivalent ownership diagnostics, or must its opaque allocation component use a conservative independently measured upper bound? How will incomplete visibility be labeled without claiming admission precision?
8. Who independently reviews the ledger and authorizes transition from design to bounded model qualification? The design author must not self-approve.
