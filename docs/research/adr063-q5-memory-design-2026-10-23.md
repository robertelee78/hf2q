## 1. Admission contract and quantities

The subsequent [host metric availability finding](adr063-q5-metric-availability-2026-10-23.md)
observes incomplete unprivileged cross-UID coverage. Competition remains Unknown;
the finding neither changes this admission contract nor approves runtime execution.

For complete conservative peak process ownership B, physical RAM P, reserve R>=12,884,901,888bytes, fresh aggregate competing-use bound C, optional independently scoped family ceiling F, require checked `B+C+R<=P` and, when applicable, `B<=F`. Also require GPU resource working-set bound G<=W under the explicit device policy below. Never add B, process footprint and Metal bytes together; they overlap. Record logical workload bytes, unique owned capacity, observed process footprint, mapped-file residency observations, and Metal resource/residency diagnostics as separate axes.

F is 116 GiB=124,554,051,584 bytes for DeepSeek (ADR042:267-275; ADR049:106). No additional whole-process F was found for Qwen3.8/Qwen3.6/Gemma4 in the revision-bound source inventory; encode `NoneWithInventory`, not `Unknown`. Their unconditional cap isP-R-C. DeepSeek cap ismin(F,P-R-C). A128 GiB host yields116GiB only at minimum reserve and zero competitors. KV budgets, model-pool budget and projector/LCP budgets remain independent component constraints, not F. Unknown required category, unknown relevant ceiling inventory, overflow, missing OS observations, changed environment or unsupported shape rejects before allocation.

C policy: enumerate all external user processes, excluding the candidate identity exactly once and including the external harness/sampler/supervisor processes in C. Sum per-process `phys_footprint` bytes conservatively, retaining shared-page overcount rather than subtracting an unproved shared fraction. Treat inaccessible/racing enumeration as unknown: retry once within freshness window, otherwise reject/stop. Required privilege is ability to enumerate and collect every relevant process; do not silently use only accessible processes. A privilege/metric preflight on this host must establish that capability before model execution. If footprint cannot be obtained, reject initial qualification rather than silently mixing RSS metrics. Do not add compressor occupancy to C: footprint/compression overlap needs platform verification; compressor/wired values are independent pressure diagnostics. R covers declared ordinary OS/kernel/headroom, not a second copy of user-process bytes. Extraordinary wired/kernel growth has its own stop signal. Never deriveP from available-now RAM then subtractC again.

This is a conservative proposed C measurement policy, not a claim that macOS footprint fully accounts clean file-backed mappings. The exact macOS accounting semantics and tool accuracy are unverified on this host. Qualification must first run a small, host-safe mapping/anonymous-allocation control comparing footprint, VM regions/residency, and Metal diagnostics. Weight accounting is source-derived conservative resource spans regardless of footprint behavior; lack of a reliable independent weight-specific residency cross-check blocks full qualification, not the pure slice.

W policy: freeze `recommended_max_working_set_size` from the actual device and every effective GPU/wired-memory setting in the receipt (including relevant `iogpu`/wired sysctl existence/value or verified unavailable state). Existing `src/setup/host.rs:93-105` queries the Metal recommended value but does not enforce Q5 admission. Use the reported recommendation as a conservative qualification bound W unless a separately reviewed, evidence-bound configured limit is approved; do not infer a larger W from successful allocation. If a binding configured GPU/wired limit is lower, use the minimum. Distinguish recommended policy value from a proved hard kernel limit. Unknown effective required settings reject runtime qualification. No change to sysctls or working-set settings is authorized by this design. G counts unique simultaneously retained Metal root resource lengths including mapped segments and queued/captured roots; compareG toW separately from hostB. This deliberately can conservatively reject a workload; do not weaken W after failure to manufacture a pass.

## 2. Closed schema: missing is never zero

For each frozen `(family, architecture, artifact set, vision, graft, speculation, persistence, thread topology, workload shape)`, generate an exact required key set. Every key must appear once as `Bound{bytes, provenance, formula_revision}`, `ProvenZero{reason, configuration_evidence}` or `Unknown{reason}`. Any missing/duplicate/Unknown key rejects admission. Do not accept arbitrary caller-provided lists or merge omitted keys to zero. A role may alias an allocation, but must name its root; the same bound cannot silently account two independent copies. All arithmetic checked u64; capacities and allocator/bucket alignment, not payload lengths, govern physical reservations.

Mandatory category groups and instances:
- Target artifact/mapped segments; independently expanded tensors; CPU load staging; metadata/tokenizer/template/allocator host baseline.
- Projector/mmproj weights, projector load staging/vision runtime scratch and image/embedding host buffers for Qwen/Gemma whenever enabled; explicit zero only for a frozen text-only configuration. Qwen3.8 launcher requires projector by default and delegates to Qwen3.6 (`serve_qwen38_opencode.sh:18-20,53`; qwen36`:96,171`). Supplied text-artifact sizes do not include these artifacts.
- Every live cache owner: slot0..3 attention parents, recurrent/conv/MTP/indexer/compressor states, and **DeepSeek loaded-model boot owner** separately. Include live_logits and host committed/token ledgers per owner.
- Per-owner/family anchor roles; multi-depth stores; temporary capture/restore copies; token/container capacity; hidden-state parent retention.
- Graft bank/metadata and planted cache-capacity effects, including DeepSeek `model.kv_graft` and Gemma grafts if configured; otherwise explicit proven-zero.
- Drafter artifacts, drafter caches, verifier/pending hidden state, proposal buffers and draft/verifier scratch, or explicit disabled proof.
- Each allowed thread's DeepSeek prefill, submission-input and decode pools; Qwen decode and weight/residency pools; family direct/persistent scratch; recorded graphs; queued command roots; CPU submission arguments. Thread identities/topology are declared, not discovered after admission.
- Host persistence construction, busy job, pending job, serialization scratch, hydration file bytes/decoded representation, and index/token containers. Include Qwen full-cache disk snapshots separately from compact serving anchors.
- Service request/input/output queues, bounded bodies/tool results, vision soft_token_data, logits, response channels, logs/receipts, HTTP/runtime worker baseline. A bounded workload still needs bounded queued requests and body limits; an unbounded host queue isUnknown.
- Transition extras: old+new growth, anchor replacement, hydration+existing valid state, model load/unload overlap, and all outstanding GPU resources until completion.

Model file identities supplied: Qwen38=16,810,714,976B; Qwen36=21,712,410,208B; Gemma4=16,796,018,144B; DeepSeek4=107,431,343,264B. They are file lengths, not complete B or G. Freeze source-matched projector/drafter artifact sizes/hashes as additional keys. DeepSeek static106.96GiB atctx262144/KV8 GiB is diagnostic only and cannot establish admission.

## 3. Verified family ownership and anchor roles

Native `MlxBuffer` clones/views shareArc storage (`buffer.rs:35-73`), root `byte_len` versus logical `data_byte_len` (`:328-337`). Count the root once across labels. Native GGUF metadata plan (`gguf/mod.rs:1710`) supplies conservative page-rounded resource-span sum without mapping model resources; device setup remains charged. Split segments can overlap a file boundary page (`:2036-2082`); keep the sum, do not subtract overlap without proof. Expanded elementwise tensors are independent roots while original mapped pages may remain. DeepSeek weight resident_bytes is logical (`deepseek4/residency.rs:203`), not that mapping bound.

DeepSeek: `Deepseek4LoadedModel::load_with_context` eagerly allocates `allocate_cache(min(context,INITIAL_CACHE_LENGTH))`, initial cap131072 (`engine_deepseek4.rs:893-898`). Slot provisioning adds four separate sessions (`:988-1003`); boot owner is not removed. Each carries potential live_logits, committed/pending anchors and token ledgers (`:265-273,291ff`). Default design **counts five owners**. Do not silently rely on a future release-boot optimization; that would be separate behavior change and validation. If boot ownership never captures anchors in frozen SlotAware mode, only a tested control-flow invariant permits those specific roles ProvenZero, while the boot cache stays charged.

For every active DeepSeek owner, count live fixed state plus committed snapshot plus pending snapshot at capture, with their actual window/conv/compressor capacities; do not multiply full append-only compressed storage by3. `load_info.rs:590-606` is live_fixed*2 for live+one recovery and therefore not a replacement for this inventory. Snapshot helper allocates source.data_byte_len without16MiB rounding (`cache.rs:1068,1096`); use exact allocated shapes plus host metadata. Window/compressed views share attention_kv (`cache.rs:411-430`) and count once. Future depth>1 explicitly multiplies owned store entries, never implicitreuse.

Qwen: live conv/recurrent scaffold already contains both double-buffer legs; current fixed estimate adds another live-scaffold equivalent for old+new anchors (`load_info.rs:571-587`) and rounds16MiB. Replace that inclusive aggregate with root inventory, not aggregate+anchors. `HybridKvSlotAnchor::total_bytes` (`kv_cache.rs:1021-1027`) is unusable as total ownership: it sums Vec::len, omits capacities/container storage/full_attn_current_len. Provide `owned_host_capacity_bound` covering each Vec capacity, outer Vec capacity, token vectors, optional cursor fields, and allocator overhead bound. Existing multi-depth store entries and pending/replacement copies count separately. A retained hidden view charges its entire parent, not~20KiB logicalrow; right-sizing is separate correctness/performance work.

Gemma: retained `prompt_anchors[slot]` (`engine.rs:11756`), request `pending_anchor` (`:6678ff`) and local `rollback_anchor` (`:6869ff`) are roles, not automatically distinct allocations: pending is moved into rollback. During snapshot replacement the old rollback value remains until new snapshot construction succeeds (`:6872-6899`), while retained prompt anchor may still exist. Initial conservative bound is **three simultaneous independent anchor payloads per slot**: retained prompt + old pending/rollback + constructing replacement, plus token/container capacities. Any lower bound needs ownership-event proof/test, not names alone. Failure role is transferred, not copied. SlotAnchor total_bytes likewise cannot substitute Vec-capacity accounting. `soft_token_data: Vec<SoftTokenData>` in prefill state (`engine.rs:6678-6683`) and its nested embeddings require explicit vision bounds.

## 4. Growth, concurrency and background quotas

One global hf2q reservation controller owns atomic reserve/commit/release. Enforce exactly one GPU allocation transition permit per process initially. Growth reserves old+entire new cache+existing anchors+copy/command resources before allocating; four simultaneous growth attempts cannot each pass a stale check. Other three slots and boot owner remain charged. Source uses mutable model/cache and migration sequence (`engine_deepseek4.rs:1066-1078`), but design does not assume that alone proves all thread topology: add an explicit transition semaphore and a test max_active_growth==1. Any future parallel-growth policy must reserve all simultaneous overlaps.

`Deepseek4Cache::migrate_from` copies into already allocated destination; after success it updates snapshot.plan=self.plan.clone (`cache.rs:769-770`). It does not allocate a new snapshot GPU payload, but plan Vec clone/metadata capacity and command lifetimes need charge. On migration failure prior valid cache/anchor remains; release only proven-unused new resources after completion. Pending snapshots and capture/restore paths remain independently inventoried.

Use static load-time reserved quotas for background host producers, avoiding per-allocation lock inversion. For DeepSeek persistence reserve one busy image + one latest-wins pending image + one constructing image + serialization scratch + one hydration image and its decoded representation, using maximum admitted image size/capacity. Source writer retainsArc<Vec<u8>>, moves pending→busy (`deepseek4_anchor.rs:131-208`), reads whole file (`:315`), and Dropjoins writer (`:218-229`); disk budget is not a RAM bound. Enforce a single serialization/hydration producer permit per persistor; otherwise multiply by declared producer concurrency. Reject an image length before allocating its body. Qwen writer independently retains busy/pendingArc<HybridKvCacheSnapshot> (`qwen35_disk_persistor.rs:56-70,126-152`); reserve full snapshot roots+writer serialization+constructing/hydrating buffers, not compact-anchor size. Gemma/LCP/hybrid persistor paths get explicit same-schema quotas orProvenZero. No background thread may exceed its reserved quota; quota exhaustion returns a typed failure without dropping prior valid state.

Thread-local pools exist per dispatch thread: DeepSeek three pools (`forward_support.rs:33-47`), Qwen DECODE_POOL (`decode_pool.rs:51-54`) and WEIGHT_POOL (`weight_pool.rs:70-73`). Declare maximum dispatcher threads and reserve each set; unregistered dispatcher creation fails before allocation. Count thread-lifetime retained pools even when idle. DeepSeek release_pool's debug_assert on in-use (`forward_support.rs:137-141`) is insufficient: full qualification requires runtime error on active release and completion-aware release, not a debug-only safety claim.

Composition with LoadedPool: existing80%-RAM handle budget remains separate. Under pool lock choose/evict candidate entries and obtain global admission reservation, then release pool lock before GPU work or background-persistor waits. Strict lock order is LoadedPool→reservation-controller; never acquire LoadedPool from reservation callbacks, never call dispatch/persistor while holding controller lock. Controller methods are bounded arithmetic/state operations. A model's reservation ticket travels with pool handle lifetime, including eviction callbacks until underlying ownership completes. Insertion fails if either component budget or whole-process/working-set bound fails. Tests exercise concurrent admission/eviction/background completion and assert lock order plus no double-release. Do not hold two locks across an allocation to make atomicity appear safe.

## 5. Narrow native counters with complete lifetime tickets

Decision: narrow resource accounting, **not** a generic allocation profiler/full global registry. However pool-only byte counters cannot cover required lifetimes. Add an opaque root `ResourceTicket{id, actual_resource_len, backing_class}` to each native-created/root-wrapped resource, cloned into all native retain paths. A small ticket state survives as long as any owning native retention remains. Views clone ticket; no new allocation. Native counters aggregate unique live tickets and state labels; labels may overlap and are not summed as separate memory.

Required retain coverage: MlxBufferStorage direct/mapped allocations; pool free/in-use; pool resident_buffers map (actual Metal handle ownership, even external registrations); residency retention if it owns handles; RecordedBinding and captured graph; encoder binding retained-root set; submitted command retain set through GPU completion AND release of every retaining command-buffer owner. Native source confirms pool holds Metal clones (`buffer_pool.rs:53-66`) and recorded bindings clone Metalhandles (`encoder.rs:1212-1224`); default command buffers retain resources (`:954-967`). A ticket only on MlxBufferStorage would decrement too early. GPU completion also does not prove ownership release: native encoder source explicitly documents completed command buffers retaining resources (`encoder.rs:1020-1026`), and `wait(&self)` leaves the command-buffer owner alive. Keep a completed-but-owner-retained state charged until all retaining command-buffer/buffer owners release. Audit raw exported command-buffer handles as well as buffer clones; an unwrapped or otherwise unaccounted owning escape blocks qualification. Every raw Metal buffer escape/import must preserve ticket or be explicitly bounded as external resource; an uninstrumented owning escape blocks qualification. Keep internal map only as necessary to identify imported/shared roots and dedup; no public pointers, stack traces, allocation sampling or generic profiler.

Expose `ResourceMemorySnapshot{unique_root_bytes, mapped_span_bytes, anonymous_resource_bytes, roots, peak_unique_bytes, pools:[{pool_id,thread_id,in_use_bucket_bytes,free_bucket_bytes,registered_root_bytes}], recorded_unique_bytes, queued_unique_bytes, completed_owner_retained_bytes, pending_residency_removal_bytes}` with documented overlapping diagnostic fields. Use monotonically assigned opaque IDs. MlxBufferPool buckets can round to nextpower2; reset moves active→free (`buffer_pool.rs:287`), clear onlyfree (`:413`), resident registrations retain root until removal and completion. Tests prove no decrement on viewdrop/poolreset/recording, completion-ticket lifetime, external-registration dedup and overlapping sets counted once. Collect all threads through ticket aggregates, not calling one TLS getter from sampler thread. Publish native changes before pinning in hf2q; no kernel relocation needed.

Scratch bound interface, implemented in hf2q family policy over native allocation rules:

`fn bound_memory(shape: &FrozenMemoryShape, phase: Phase, transition: &TransitionState, formulas: &VersionedAllocationRules) -> Result<MemoryBound, UnknownBound>`

`FrozenMemoryShape` includes family/config dimensions,4slots plusbootowner, per-slot context/prompt/result and current/proposed capacity, prefill/cohort rows, active lane mix, dtype/quantization, experts/topk/head/index dimensions, dispatcher count, speculation width/depth/draftcfg, vision bounds, persistence producers/limits and maximum outstanding submissions. `MemoryBound` returns closed per-category host/shared-resource byte bounds, allocation/root lifetime graph, scratch peaks per thread/phase, CPU submission buffers, queued/captured retained sets, and overlap transitions. Use checked arithmetic and native bucket/alignment rules. Unrecognized shape returnsUnknown; favorable observed high-water never substitutes for a bound. Scratch formulas/runtime validation values remain pending. The interface can exist and reject now; no model execution to discover an unbounded shape.

## 6. External harness watchdog and bounded failure ending

Run candidate/stock/peer each as a separate controlled process group under an external harness that owns sampler and kill authority. Sampler must not depend on target heartbeat, target allocator or target scheduler to observe pressure. Move reusable Darwin VM helper logic out of its current test-only helper (`real_artifact_decode_cohort_tests.rs:214,292`) into a harness module/tool; no production dependency on a test module. Sampler captures timestamp/boot epoch, pressure, VM deltas, target footprint, competing processes, weight-specific VM/Metal cross-check and target allocation receipts. Store receipts outside target memory/disk persistence directories.

Proposed protected-run constants to implement/test with small controls before timing:250 ms sample period,1 s maximum sample age/gap, detection response <=1 s after a captured violating sample,2 s graceful drain deadline after stop command, then SIGTERM process-group deadline 1 s, then SIGKILL, and 30 s recovery observation deadline. These are design choices, not measured guarantees; inability to demonstrate them blocks runtime qualification. Critical pressure invokes immediate SIGKILL (no grace), because already queued GPU work cannot be assumed cancellable safely. Other projected breach/stale telemetry/unexplained growth/working-set violation triggers stop-new-dispatch and persistence enqueue, bounded completion drain, then escalation. Stalled sampler is detected by separate harness supervisor heartbeat; target alive without sampler is killed, not allowed to continue.

Stop handlers close admission, cancel pending requests, forbid new persistence jobs, and wait only within the shared2 s deadline for GPU/worker/persistor completion. Source supervisor timeout merely poisons and requires process restart (`engine_supervisor.rs:348-360`); this design does not rely on that as exit. Existing persistor Drop.join can hang, so harness terminates process instead of waiting indefinitely. Never publish a partial anchor on failure; existing atomic-temp-file protocol remains required. A forcedkill invalidates the run and quarantines that run's persistence directory; next run must not hydrate from it without validated complete-file checks.

Recovery requires processgroup terminated/reaped, no listeners/child processes, memory/pressure stable for at least 5 s within 30 s, and competing-use baseline re-established. Targetownership is zero only after process exit, not after a Rustdrop/log. Compare independent OS/Metal diagnostics to pre-runbaseline with declared noise allowance; clean reclaimable file cache need not produce identical freeRAM. Persistent pressure, unexplained wired/resource growth or cleanup timeout blocks next load and records failure. No next engine starts untilrecovery passes. A missing final target receipt invalidates the qualification run; cleanup must never depend on querying a dead target for final command reports. External process/listener and OS/Metal quiescence observations gate cleanup and the next load. Native completed callbacks help in-process accounting but cannot prove postkill GPU reclamation alone; external observations remain required.

Protected initial rule: zero growth in swapouts and swapused during protected measurement; compression/wired/footprint noise allowances must be justified by an idle control and frozen before timing, otherwiseUnknown and fail. Existing launcher8 GiB startup swap/compressor caps are not allowable run deltas. Existing protected gate5 s sampling is not evidence for the proposed1 s bound. Freeze actual policy and measured overhead in packet, identically forstock/candidate/reference or account overhead independently.

## 7. Slices and controls

Slice 1 is hf2q-only pure ledger, schema, cap arithmetic, ownership events and receipts. It changes no native code, loads no models and cannot grant runtime admission. It implements the complete required-key schema, but Unknown scratch, OS or GPU evidence makes every real-model packet reject. Implement Bound/ProvenZero/Unknown, root/view/release events, checked peak transitions and `admit(B, F_state, P, R, C, G, W)` with explicit None versus Unknown family ceiling. This groundwork is not full Q5 qualification and does not reduce Q5 scope.

Slice 2 closes native lifetime counters and cross-thread/persistor quotas, implements formula coverage, atomic reservations and the external watchdog, and publishes/pins native if changed. Use small controls without host exhaustion. Slice 3 independently reviews complete shapes/bounds, host metric calibration and watchdog guarantees, obtains a separate recorded runtime decision after F1/predecessors, then executes bounded qualification for all four families. DeepSeek runs last, only after complete conservative admission; never load full context to discover an unknown bound. Run stock, candidate and peer sequentially, with no DeepSeek co-residency. Q5 acceptance delivers a credible matched memory measurement envelope and preserves quality/serving correctness; all-four speed wins remain Q3/Q4.

Required negative controls:

- Boot cache plus four slots; all anchor roles and replacement alias versus new copy; two thread-local dispatcher sets; tiny view retaining large parent; mapped segment padding.
- Full Qwen persistence snapshots; busy plus pending plus constructing plus hydration images; projector and soft-token buffers; graft bank and live logits.
- Four racing growth reservations and enforced serialization; migration failure preserving prior state; overflow; missing/duplicate category; Unknown scratch; None versus Unknown ceiling.
- Pool reset/free/clear and registered roots; captured/queued ticket lifetime beyond wrapper drop; uninstrumented imported raw handle rejection.
- Aggregate competitors, inaccessible PID and stale observations; independent G<=W and host/family caps; frozen workload shrink rejection.
- Target wedge and persistor drain hang forcing termination; sampler hang forcing termination; post-kill recovery timeout preventing the next load. Do not intentionally exhaust host memory.

The bounded real matrix freezes artifact hashes including projector/drafter, four occupied slots, context/result limits, largest tool-result bursts, vision/graft/persistence/speculation, dispatcher/outstanding-command counts and cohort shapes. Exercise growth, capture, rollback, divergence, tool continuation, cancellation, hydration and mixed prefill/decode. Report projected/observed peaks, pressure/residency/swap/compression, cleanup, cached tokens, TTFT, prefill/decode and semantic correctness. The peer's opaque component requires a conservative independently justified bound plus observations. Failure to admit a matched peer means no speed verdict, not permission to reduce the task.
